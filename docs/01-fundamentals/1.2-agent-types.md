# 1.2 三类分类维度：同一个模型，什么时候该「想久一点」

::: tip 一句话结论
分类不是为了背名词，而是为了回答一个工程问题：**这个任务该花多少"思考预算"？**
预算给少了会短视，给多了会又慢又贵还可能想歪。
:::

## 1.2.1 维度一：按内部决策架构分

这就是 1.1.3 那张"五级台阶"表（简单反射 → 基于模型 → 基于目标 → 基于效用 → 学习型）。
在 LLM 时代，它退化成一个更实用的问句：

> 这个任务的"下一步"，能不能靠**当前上下文**直接推出来？

- 能 → 单次调用就够（不需要循环）
- 不能，但缺的信息可以查 → 需要工具 + 循环
- 不能，且需要权衡多个目标 → 需要显式的效用判断（通常写进系统提示，或用评分器/评估器）

## 1.2.2 维度二：按时间与反应性分（本节重点）

这是三个维度里**唯一直接对应成本与体验**的。拖动下面的滑块，看不同预算下的取舍：

<TradeoffCurve />


三类形态，落到工程上分别是：

| 形态 | 决策方式 | 延迟量级 | 典型实现 |
| :--- | :--- | :--- | :--- |
| 反应式 | 感知 → 动作，直接映射 | 毫秒 | 规则引擎、风控拦截、缓存命中 |
| 规划式 | 先搜索未来，再落子 | 秒~分钟 | 多步规划、长思维链、深度研究 |
| 混合式 | 大方向规划 + 小步即时反馈 | 秒 | **Agent Loop**（本节的主角） |

::: tip 为什么 2026 年的主流是"混合式"
因为 Agent Loop 天然就是这个形状：
"思考"阶段做规划（审议），"行动/观察"阶段立刻拿环境反馈（反应），
把一个长任务切成了一串「规划—反应」的微循环。
所以你不需要在两者之间二选一，**循环本身就是那个混合器**。
:::

> 神经网络擅长"**看起来像**"，符号系统擅长"**一定成立**"。

原书用丹尼尔·卡尼曼的"双系统"做类比，这个类比在 2024 年还只是隐喻，**到 2026 年已经变成了产品形态**：

| | System 1（快思考） | System 2（慢思考） |
| :--- | :--- | :--- |
| 人类的对应 | 直觉、脱口而出 | 演算、权衡 |
| 模型的对应 | 直接生成答案 | 先产出思维链，再给答案 |
| 2023 年怎么做 | 默认行为 | 提示词里写"请一步步思考" |
| **2026 年怎么做** | 普通对话模型 | **推理模型**：思考是原生能力，有独立预算 |
| 成本 | 低 | **思考 token 也计费**，可能比答案还长 |

## 1.2.4 一个必须亲手验证的事实：思考是两份产物

这是我在本项目里真实跑出来的返回结构（`glm-5.3`，一次工具调用请求）：

```json
{
  "role": "assistant",
  "reasoning_content": "The user is asking about the weather in Chengdu... I should call get_weather with the city parameter.",
  "content": null,
  "tool_calls": [{ "function": { "name": "get_weather", "arguments": "{\"city\":\"成都\"}" } }]
}
```

注意三件事：

1. **`content` 是 `null`**——模型决定直接调工具时，它不会写"我要查天气"这句话；
2. 真正的"思考"在 **`reasoning_content`** 里，这是一个**非标准但已事实通用**的字段（DeepSeek、GLM、Qwen 等推理模型都这么返回）；
3. 这段思考**照样计费**，而且不会出现在最终回答里。

::: warning 这就是"抄旧教程"会踩的坑
2024 年的代码几乎都只读 `message.content`。放到推理模型上，结果就是：
**思考区永远是空的，而你已经为那些思考 token 付了钱。**
本项目在 `first-agent.ts` 里把两者拆成了两个事件：`reasoning`（思维链）和 `thought`（可见回答）。
:::

## 1.2.5 前端视角：这不是"选模型"，是选三角

作为前端工程师，你其实每天都在做同类权衡——首屏时间、包体积、交互流畅度三者不可兼得。
Agent 这边是同一道题：

```text
        质量
         ▲
        ╱ ╲
       ╱   ╲
   成本 ◀───▶ 延迟
```

- 想更快 → 换小模型 / 降低思考预算 / 减少循环轮数
- 想更好 → 加思考预算 / 加验证步骤（自我反思）/ 换更大模型
- 想更省 → 裁上下文 / 缓存系统提示 / 把简单分支交给规则

::: tip 一个反直觉的结论
**"让模型多想一会儿"不是免费的午餐。** 对"把这段话翻译成英文"这种任务，
开最高思考预算只会更慢更贵，质量提升接近 0。判断标准是：
**任务是否存在"需要中间推导才能得出答案"的结构**。有就值得想，没有就是浪费。
:::

## 1.2.6 常见误区

::: warning 误区：混合式 = 把两个模型拼起来
不是。混合指的是**同一套循环里既有规划也有即时反馈**，通常由同一个模型完成。
真正的"大小模型接力"是另一种优化手段（路由），属于成本工程，不是分类维度。
:::

::: warning 误区：符号系统已经没用了
恰恰相反。Zod Schema、JSON Schema、TypeScript 类型、SQL、正则——这些确定性代码
正是把模型"看起来像"约束成"一定成立"的手段。本项目所有工具参数都用 Zod 校验，
就是神经符号主义最小成本的落地。
:::

## 小结

- 三个维度里，**时间/反应性**最值得你花时间，因为它直接决定成本与体验。
- 2026 年的"双系统"不再是提示词技巧，而是**推理模型的原生能力**，且思考要单独计费。
- 判断要不要"想久一点"，看任务是否存在必须中间推导的结构。
